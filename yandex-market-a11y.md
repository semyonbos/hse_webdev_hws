# Анализ проблем доступности сайта Яндекс.Маркет

## Описание сайта

Яндекс.Маркет (https://market.yandex.ru/) — один из крупнейших российских маркетплейсов, позволяющий пользователям искать, сравнивать и покупать товары от различных продавцов. Сайт содержит сложную навигацию с множеством фильтров, каталогов товаров, рейтинговых систем, интерактивных элементов и динамически обновляемого контента. Платформа используется миллионами пользователей в месяц, включая людей с различными ограничениями по здоровью.

## Выявленные проблемы доступности

### Проблема 1: Сложность навигации через фильтры со слабой поддержкой клавиатурного управления

#### Описание проблемы

На странице поиска товаров Яндекс.Маркета расположена сложная система фильтров (категории, цена, бренд, рейтинг и т.д.), которая не полностью поддерживает навигацию через клавиатуру. Многие фильтры реализованы через выпадающие меню (dropdown), которые открываются только при наведении мышью или нажатии, но не всегда правильно работают с использованием только клавиши Tab и стрелок.

**Конкретные проблемы:**

1. **Отсутствие явного видимого фокуса** — когда пользователь использует только клавиатуру для навигации по фильтрам, визуальный индикатор фокуса (обводка, изменение цвета) может быть слабо заметным или отсутствовать вовсе. Это затрудняет отслеживание текущей позиции для пользователей с нарушениями внимания или когнитивными особенностями.

2. **Ловушки фокуса в модальных окнах фильтров** — когда пользователь открывает окно со всеми фильтрами ("Перейти ко всем фильтрам"), фокус может застрять внутри этого окна, и пользователь не может выйти из него, используя только клавиши Escape и Tab.

3. **Проблемы с управлением выпадающими меню** — некоторые выпадающие меню требуют использования стрелок, другие требуют использования пробела или Enter, что неконсистентно и запутанно для пользователей вспомогательных технологий.

4. **Отсутствие поддержки ARIA-атрибутов** — многие элементы фильтров не содержат необходимых ARIA-атрибутов (`aria-expanded`, `aria-labelledby`, `aria-controls`), которые помогают скринридерам понять состояние элементов (раскрыто/свернуто).

#### Влияние на пользователей

- **Пользователи со слабой моторикой** (паралич, тремор, отсутствие рук) не могут использовать мышь и полностью зависят от клавиатурной навигации. Сложная система фильтров заставляет их искать нужный товар вслепую.

- **Пользователи скринридеров** (слепые люди) не получают информацию о состоянии фильтров, не знают, какие фильтры применены, и не могут понять, как навигировать по сложной системе управления.

- **Люди с когнитивными особенностями** запутываются в непредсказуемом поведении элементов управления и отсутствии четких индикаторов фокуса.

- **Пользователи на мобильных устройствах** (где "наведение" невозможно) не могут получить доступ к некоторым скрытым элементам меню.

### Проблема 2: Недостаточное описание элементов (отсутствие ARIA-лейблов и alt-текстов для икон)

#### Описание проблемы

На сайте Яндекс.Маркета используется множество иконок (звезды для рейтинга, сердечко для "Избранного", иконки доставки, и т.д.) без текстовых описаний или атрибутов `alt` и `aria-label`. Кроме того, некоторые кнопки содержат только иконки без видимого текста.

**Конкретные примеры:**

1. **Иконка рейтинга** — обычно отображается как звезда с числом (★ 4.5), но если это реализовано как изображение без alt-текста, скринридер не сообщает о рейтинге.

2. **Кнопка "В избранное"** — часто реализована как иконка сердечка без подписи. Скринридер озвучивает только "кнопка" без понимания, что это за кнопка.

3. **Иконки доставки и способов оплаты** — используются для показа способов доставки (самовывоз, доставка на дом) и оплаты, но часто без пояснительного текста.

#### Примеры проблемного кода

```html
<!-- Проблемный: иконка без описания -->
<button class="favorite-btn" onclick="addToFavorites()">
  <svg>...</svg>
</button>

<!-- Неправильно: без описания для изображения -->
<span class="rating">
  <img src="star.png" /> 4.5
</span>
```

## Нормативная база

Согласно **ГОСТ Р 52872-2019** "Интернет-ресурсы и другая информация и услуги на ней. Требования доступности для инвалидов", веб-ресурсы должны соответствовать требованиям **WCAG 2.1 уровня AA**, которые включают:

- **1.4.3 Контраст (минимум)** — текст и изображения текста должны иметь контраст не менее 4.5:1
- **2.1.1 Клавиатура** — все функции должны быть доступны через клавиатуру
- **2.1.2 Нет ловушки клавиатуры** — фокус не должен застревать в элементах
- **1.1.1 Альтернативный текст** — все нетекстовые элементы должны иметь текстовые альтернативы
- **4.1.2 Имя, роль, значение** — все компоненты пользовательского интерфейса должны иметь доступное имя и роль

## Предложения по решению проблем

### Решение проблемы 1: Улучшение клавиатурной навигации в фильтрах

**Основные меры:**

1. **Использовать правильные HTML-элементы** — заменить `<div>` на семантические элементы `<button>` и `<fieldset>/<legend>` для создания предсказуемого поведения фильтров.

2. **Добавить ARIA-атрибуты** — использовать `aria-expanded`, `aria-controls`, `aria-labelledby` для описания состояния и взаимосвязей между элементами фильтров. Это позволит скринридерам корректно информировать пользователей о раскрытом/свернутом состоянии.

3. **Обеспечить видимый фокус** — применить четкую визуальную обводку (outline) и изменение цвета при фокусе на элементах с помощью CSS `:focus-visible`. Минимальная ширина обводки должна быть 2-3 пикселя с контрастом не менее 3:1.

4. **Предотвратить ловушки фокуса** — убедиться, что клавиша Escape закрывает модальные окна фильтров и возвращает фокус на кнопку, которая их открыла. Фокус должен циклически перемещаться внутри модальных окон (Tab на последнем элементе переходит на первый).

5. **Стандартизировать управление** — использовать согласованные горячие клавиши для всех типов фильтров (стрелки для навигации, Enter для активации, Escape для закрытия).

**Пример правильной структуры:**

```html
<button aria-expanded="false" aria-controls="price-filter-content">
  Цена
</button>

<div id="price-filter-content" hidden aria-hidden="true">
  <label for="price-from">Цена от</label>
  <input type="number" id="price-from" />
  <button type="submit">Применить</button>
</div>
```

### Решение проблемы 2: Добавление описаний для иконок и элементов управления

**Основные меры:**

1. **Добавить aria-label для кнопок с иконками** — каждая кнопка, содержащая только иконку, должна иметь атрибут `aria-label` с понятным описанием функции. Например: `aria-label="Добавить в избранное"`.

2. **Использовать alt-текст для изображений** — все изображения рейтингов, иконки способов доставки и оплаты должны иметь достаточное описание в атрибуте `alt` или быть помечены как декоративные с `aria-hidden="true"`.

3. **Скрывать декоративные иконки** — если иконка только визуальный элемент и информация продублирована в текст, использовать `aria-hidden="true"` для предотвращения озвучивания.

4. **Указывать изменяемые состояния** — для кнопок, которые меняют состояние (например, "В избранное" может быть добавлено или удалено), использовать `aria-pressed` или `aria-checked` для информирования о текущем состоянии.

**Пример правильной реализации:**

```html
<!-- Кнопка с aria-label -->
<button aria-label="Добавить в избранное">
  <svg aria-hidden="true">...</svg>
</button>

<!-- Изображение с alt-текстом -->
<img src="stars.png" alt="4.5 звезды из 5" />

<!-- Рейтинг со скринридером -->
<div aria-label="Рейтинг: 4.5 звезды из 5 звезд">
  <span aria-hidden="true">★★★★☆</span>
  <span>4.5</span>
</div>
```

### Решение проблемы 3: Повышение контраста

**Основные меры:**

1. **Пересмотреть цветовую палитру** — заменить светлые серые цвета на более темные оттенки, обеспечивающие контраст не менее 4.5:1 для обычного текста и 3:1 для крупного текста (18pt или больше) в соответствии с WCAG 2.1 AA.

2. **Применить правило ко всему тексту** — особое внимание к вторичному текст (характеристикам товаров, условиям доставки, старым ценам при наличии скидки), который часто использует низкий контраст.

3. **Использовать инструменты для проверки** — проверить контраст всех пар цветов (текст + фон) с помощью WebAIM Contrast Checker или встроенного Lighthouse в Chrome DevTools перед развертыванием.

4. **Тестировать в разных условиях** — убедиться, что текст читаемо выглядит не только на экране дома, но и при ярком солнечном свете на мобильном устройстве.

**Рекомендуемые изменения цветов:**

| Элемент | Текущий цвет | Рекомендуемый цвет | Контраст |
|---------|-------------|-----------------|----------|
| Вторичный текст | #999999 | #555555 | 7.5:1 ✓ |
| Характеристики товара | #888888 | #333333 | 12.6:1 ✓ |
| Старая цена (зачеркнутая) | #cccccc | #888888 | 4.5:1 ✓ |

## Инструменты для проверки доступности

**Автоматизированные инструменты:**
- **Lighthouse** (встроен в Chrome DevTools, вкладка Lighthouse → Accessibility)
- **WAVE** (браузерное расширение для быстрой визуальной диагностики)
- **Axe DevTools** (подробный анализ проблем доступности)
- **WebAIM Contrast Checker** (проверка контрастности цветов)

**Инструменты для ручного тестирования:**
- **NVDA** (https://www.nvaccess.org/ — бесплатный скринридер для Windows)
- **VoiceOver** (встроен в macOS и iOS)
- **Клавиатурное тестирование** — проверить, что все функции работают только с использованием Tab, стрелок, Enter и Escape

## Заключение

Выявленные проблемы с доступностью на Яндекс.Маркете (сложность фильтров, отсутствие ARIA-атрибутов, недостаточный контраст) являются серьезными барьерами для пользователей с ограничениями по здоровью. Реализация предложенных решений расширит аудиторию платформы, улучшит пользовательский опыт для всех и обеспечит соответствие российским стандартам доступности (ГОСТ Р 52872-2019 на основе WCAG 2.1 AA).
